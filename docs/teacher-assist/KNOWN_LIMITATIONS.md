# TeacherAssist Known Limitations

- Current planning route may still be named `/teacher-assist/weekly-planning`, even though the product direction is broader instructional planning.
- Real provider calls are disabled by default.
- Mock generation is currently the only safe default provider.
- OCR extraction remains mock-first by default; real OCR providers are implemented but disabled unless explicitly enabled in server configuration.
- Uploaded resource parsing is represented by extraction jobs and preview records, not real document understanding.
- QR assignment-page identity is implemented only for generated printable packets; scan/upload ingestion is not implemented yet.
- Printable assignment templates are currently limited to browser-print HTML output.
- Grading assistant workflows have not been implemented yet.
- TEKS mastery matrix foundation is implemented with teacher-confirmed manual commits, correction/reversal lineage, and anonymous STUDENT # tracking. Phase 27 adds read-only heatmaps, rules-based reteach insights, and operational mastery dashboards. Phase 29 adds mock AI reteach plan drafts with teacher-required review and version history; real-provider reteach AI, automatic publish, and district analytics remain deferred.
- Newsletter/communication assistant supports mock AI weekly newsletter drafts with teacher review, versioning, and HTML/PDF/DOCX export. TeacherAssist never sends messages automatically; real-provider newsletter AI and outbound send integrations remain deferred.
- Lesson effectiveness scores are read-only analytics derived from assignments, mastery, grading outcomes, and reteach activity. Reflection workspaces support mock AI suggestions only; nothing updates grading, mastery, or parent communication automatically.
- Phase 31.5 consolidates teacher UX around Home, Work Queue, and class workspaces, but legacy routes (`/today`, `/workspace`, `/actions`) remain available. Onboarding progress is computed from setup counts rather than explicit step-by-step teacher confirmation. Smart shortcuts infer usage from recent assignments/plans; there is no behavioral analytics pipeline.
- Resource unlink/remove flows may still be deferred.
- Static-export frontend constraints may influence route design.
- TeacherAssist currently resolves the first accessible TeacherAssist tenant membership.
- Shared instructional plan discovery is implemented as a foundation, but collaborative team workflows are still limited.
- Sharing/template mutation is currently owner-only; tenant-admin moderation flows are not implemented yet.
- Teacher personalization branching/versioning has not been implemented yet.
- Annual curriculum rollover is implemented as a plan-copy foundation, but broader multi-artifact rollover is not implemented yet.
- Cross-school-year instructional asset reuse is currently limited to instructional-plan copying.
- Instructional asset library workflows beyond plans have not been implemented yet.
- Target grading-period remapping UI has not been implemented yet.
- Section regeneration currently saves directly to a new version; preview-before-save is not implemented yet.
- Dedicated TeacherAssist worker execution is implemented as a foundation, but deployment/runtime orchestration still depends on environment wiring.
- Workflow metadata is surfaced in the planning workspace, but there is not yet a separate rich workflow-detail operations screen.
- Real-provider execution is available only for instructional-plan generation and only when explicit backend config, API key, allowlisted model, and cost controls are in place.
- Provider support is currently limited to the guarded OpenAI-compatible path plus deterministic mock mode.
- Shared-plan regeneration does not yet add collaborative approval or owner-protection workflows beyond existing visibility rules.
- The assignment workspace is teacher-owned and single-user; collaborative assignment governance is not implemented yet.
- Printable assignment packets are assignment-scoped and teacher-owned; broader packet sharing/governance workflows are not implemented yet.
- Uploaded student-work intake now supports async extraction jobs, preview persistence, and teacher review drill-down, but real OCR quality and handwriting extraction are still limited.
- Grading review supports manual teacher confirmation and optional guarded AI draft suggestions. Teacher-confirmed manual gradebook commits are available via the Gradebook workspace; teacher-confirmed mastery tracking is available via the Mastery workspace. Parent communication, LMS sync, and SIS integration are not implemented yet.
- Assignment resource-link editing exists only as a backend foundation and starter-copy seam; the frontend does not yet expose a richer assignment-resource editor.
- The unified workspace now includes extraction remediation drill-down, but live push notifications and websocket-based updates are not implemented.
- The unified workspace is optimized for operational summaries and attention surfacing; `/teacher-assist/actions` now provides the deeper cross-module action routing layer, but bulk remediation orchestration is still deferred.
- TeacherAssist activity events are stored as append-only relational records for timeline/query use; broader event-stream infrastructure is not implemented.
- TeacherAssist frontend validation remains lint/build only because the repo does not yet include a wired frontend test harness for this product area.
- TeacherAssist object storage now supports local and private S3 backends, but direct-browser uploads are not implemented yet.
- Stored TeacherAssist downloads use temporary backend-generated URLs only; public bucket/CDN delivery is intentionally not supported.
- Printable packet HTML views are still the active print/export surface; persisted packet/export artifacts in object storage remain a later phase.
- Lifecycle cleanup is currently infrastructure-guided for S3 `temp/` and `exports/` prefixes only; app-managed retention jobs are not implemented yet.
- Extraction review notes and issue reasons are currently stored in record metadata rather than dedicated columns.
- External-link resources do not have uploaded file bodies, so extraction applies only to stored resource files and uploaded student-work artifacts.
- Extraction completion and teacher review do not automatically create grading reviews, gradebook commits, mastery updates, or parent communication artifacts. Gradebook commits require a separate teacher-confirmed manual action (Phase 24). The action workspace (Phase 25) surfaces ready-to-commit reviews but does not auto-commit.
- Education Catalog browse (Phase 32.2/32.2A) inherits instructional hierarchy from teacher school assignments via the centralized `catalog_access` service. Teachers browse read-only at `/teacher-assist/catalog`; root admins manage catalog data at `/teacher-assist/administration/education-catalog`. Legacy `/v1/teacher-assist/education-catalog/my-context` remains a flat snapshot for backward compatibility; new browse and future planning integration should use `/v1/teacher-assist/catalog/*` and `catalog_access`.
- Campus administrator role is intentionally deferred for catalog access. Campus admin users currently receive teacher-equivalent catalog browse permissions; root admins retain full catalog management access.
- Catalog-aware lesson generation, mastery tracking, and planning workflows are not wired to the education catalog yet (Phase 32.2A is browse/consumption only).
- Phase 33 introduces catalog-aligned pacing guides as the planning backbone foundation. District guides are root-admin managed; teachers can browse and copy district guides into personal teacher guides. Legacy pacing item workflows remain available at `/v1/teacher-assist/legacy/pacing-guides` and `/pacing-guides/{id}/items`. Instructional plans (`weekly_plans`) expose optional `pacing_guide_period_id` but plan creation does not require pacing guide linkage yet. Grade-level guide authorization, period delete/reorder UI, objective inheritance into plans, and cross-tenant district guide sharing are deferred.
- Phase 34 makes the pacing guide the teacher home anchor: active guide preference persists per teacher, current week resolves from guide dates with optional manual week override, and Home/Planning workspace surfaces current week objectives/resources/notes plus timeline and objective coverage read models. Instructional plan, assignment, and newsletter flows accept pacing-week launch context via `?pacing_period_id=` and planning-draft `pacing_guide_period_id` prefill. Objective coverage statuses are heuristic (covered/planned/not scheduled) and do not yet drive mastery automation. Re-seeding existing pacing guides does not retroactively add grading-period/unit hierarchy unless guides are recreated.
- Phase 35 centers generation on the selected pacing week: `WeekContextService` produces a normalized week DTO consumed by week-scoped generate APIs; `teacher_assist_generated_artifacts` tracks lesson plans, assignments, quizzes, rubrics, newsletters, and parent-communication drafts with resource/objective traceability metadata. Home and pacing quick actions route to `/teacher-assist/planning/weeks`. Quiz/rubric generation uses assignment infrastructure foundations (question bank / rubric JSON scaffolds) rather than standalone engines. Parent communication is draft/registry only with no outbound send. Export artifact generation is not yet week-aware. Legacy direct-create routes remain available.
- Phase 36 adds instructional asset reuse foundations: `InstructionalAssetReuseService` scores reusable weeks/artifacts/templates/plans; duplicate week, generate next week, template library, rollover v2, planning groups, and teacher efficiency dashboard APIs track reuse events with estimated minutes saved. Home and week workspace surface recommended reuse, recent templates, and time-saved metrics. Template apply and week duplication reuse the week duplication service; artifact-level duplicate remains shallow. Team pacing guide ownership fields exist on `pacing_guides` but guide create/update UI does not yet expose ownership/visibility controls. Rollover v2 copies instructional plans when selected but has no dedicated teacher UI yet. No collaborative editing, marketplace monetization, district analytics, or automatic publishing.
- Phase 37 introduces the instructional week as the teacher operating system: persisted `instructional_weeks` and `instructional_week_objectives` form the execution layer above pacing guide weeks; the primary workspace lives at `/teacher-assist/week/[id]` with tabbed lessons/assignments/assessments/resources/newsletter/mastery/timeline/action-center views. Existing artifacts remain reachable via nullable `instructional_week_id` FKs and legacy `/teacher-assist/planning/weeks` pacing-period workspace. Setting an active pacing guide auto-creates a DRAFT instructional week for the resolved current period; teachers can also create weeks explicitly from pacing periods. Generated artifacts auto-link to an existing instructional week for the same pacing period. Week snapshots freeze workspace JSON for audit/reuse. Mastery tab is read-model composition only. No AI copilot, collaborative editing, SIS/LMS integration, or parent communication automation.
- Phase 38 closes the instructional feedback loop from assignment through gradebook, mastery, and reteach: `teacher_assist_instructional_evidence` stores teacher-confirmed evidence; `ObjectivePerformanceService` computes transparent objective performance; assignment coverage, mastery dashboard v2, student support groups, reteach workspace (`/teacher-assist/reteach`), instructional reflections, week closure checklist, and auto-generated week summaries connect planning to improvement. Gradebook v2 surfaces objective alignment and mastery impact without auto-committing mastery updates. Reteach effectiveness tracks before/after improvement with teacher reflection. Recommendation engine v2 and home instructional health cards suggest actions but require teacher review. No SIS/LMS integration, district analytics, predictive AI scoring, auto-grade commits, or auto-mastery commits.
- Phase 39 adds Teacher Copilot as a context-aware instructional coach: `teacher_copilot_sessions` / `teacher_copilot_messages` persist conversation history with `context_snapshot` audit payloads and `TeacherAssistAIUsageEvent` cost tracking (`feature=teacher_copilot`). `TeacherContextEngine` assembles context packets from instructional week, pacing guide, objectives, mastery, reteach workspace, assessments, resources, and reflections. Mock-first intent handlers return explainable `why`, `evidence`, `source_data`, and `confidence` for objective analysis, student support, small group drafts, week/grading period summaries, resource recommendations, lesson gap analysis, reteach assistant, reflection patterns, and root-admin catalog/pacing gap queries. Real OpenAI provider mode is guarded and rejected in this phase. Copilot may recommend and summarize only — it does not change grades, commit mastery, publish plans, send communications, or mutate instructional records automatically. Home surfaces Ask Teacher Copilot, suggested actions, and weekly summary links. Mastery v2 / gradebook v2 dedicated UI upgrades and rich conversational LLM responses remain deferred.
- Phase 41 prepares TeacherAssist for teacher pilots without adding major instructional domains: `ProductCompletionReview` and `FEATURE_INVENTORY.md` document implemented/partial/deferred features; primary navigation follows Home → Instructional Weeks → Pacing → Assignments → Mastery → Resources → Communication → Copilot; pilot feedback workspace (`/teacher-assist/feedback`) captures category/severity/feature-area reports; usage metrics foundation tracks login and feature counters; root-admin system health dashboard (`/teacher-assist/administration/system-health`) surfaces users, jobs, storage, copilot usage, and seed validation; deployment/production/pilot checklists document AWS, env vars, migrations, and validation steps. UI consistency uses shared dashboard headers and inline-only alerts (no toasts). LMS/SIS, parent portal, district analytics, and billing remain deferred.
- Approved extracted text is now consumable through read-only grading-prep context/summary APIs after teacher approval, but AI grading and analytics workflows are not wired yet.
